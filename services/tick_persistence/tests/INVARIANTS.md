# tick_persistence invariants and mirror-test audit

These invariants come from `docs/design/20-data-contracts.md`: Kafka offset is lineage, not business identity; latest price is event-time ordered, not persistence-time ordered; and replay must be deterministic. KIS does **not** expose an execution-id field, so future implementation tasks must either add a real provider identity or define a deterministic surrogate from the available payload fields.

## System invariants

| ID | Invariant | Natural-language definition | Verification method |
|---|---|---|---|
| I1 | Idempotency | The same logical tick, identified by the same `event_id`, may be delivered or replayed N times through different Kafka offsets, but bronze stores exactly one row for that logical event. Kafka `topic:partition:offset` remains audit lineage only. | Property test: generate one tick payload and one deterministic `event_id`, insert it N times with varied Kafka metadata, then assert `count(*) where event_id = key` is 1 and downstream silver/snapshot counts are unchanged by duplicates. |
| I2 | Total-order preservation | For one symbol, ticks may arrive in arbitrary order; after all are processed, `serving.symbol_snapshot` reflects the tick with the maximum canonical event timestamp, not the last arrival or latest `persisted_at`. | Property test: generate same-symbol ticks with increasing canonical `event_ts`, permute arrival order, process all ticks, then assert snapshot price/time/cumulative volume equals the max-`event_ts` tick. |
| I3 | Monotonicity | For one symbol, the snapshot ordering key (`event_ts`, plus the deterministic tie-breaker once defined) never moves backward as later or stale ticks arrive. A stale tick may be recorded in bronze, but it must not regress serving state. | Stateful/property test: process a stream containing fresh and stale ticks; after each tick, read snapshot and assert its ordering key is `>=` the previously observed ordering key. |
| I4 | Boundary safety | Date/time boundaries such as `235959 -> 000001` and cross-day replay must compare by canonical `TIMESTAMPTZ`, so midnight does not invert order when text `HHMMSS` wraps. | Boundary property/example test: build ticks around midnight with adjacent `business_date` values, canonicalize to KST `TIMESTAMPTZ`, process in both arrival orders, and assert the cross-day newer tick wins. |
| I5 | `event_id` determinism | The same input tick produces the same logical id across process/session/restart boundaries. The id must not depend on UUID4 randomness, object identity, Kafka offset, session state, or insertion time. | Property/golden test: generate or fixture payloads, compute `event_id` repeatedly in separate calls and after simulated restart, then assert identical ids; mutate one identity field and assert the id changes or the documented collision policy applies. |

## Mirror-test audit

| File | Test | Classification | Audit note / migration path |
|---|---|---|---|
| `test_repository.py` | `test_bronze_insert_round_trip` | mirror | Verifies ORM column mapping and current Kafka lineage persistence. It asserts the private implementation shape of `tick_dedupe_key == "stock-ticks:2:456"`, which mirrors the offset-derived key rejected by the identity contract. Keep as mapping coverage only; migrate idempotency coverage to I1 with logical `event_id`. |
| `test_repository.py` | `test_bronze_duplicate_message_is_skipped` | mirror | Covers duplicate delivery of the exact same Kafka position, not duplicate logical ticks republished at different offsets. It also asserts the exact offset-derived dedupe string. Replace invariant coverage with I1. |
| `test_repository.py` | `test_silver_upsert_is_idempotent_and_updates` | invariant-checking | Externally checks one row per `(symbol, bucket_start)` and update semantics for a 5-minute bar. This remains useful for silver repository idempotence, but it is not sufficient for stale-price snapshot ordering. |
| `test_repository.py` | `test_silver_load_bar_state_absent_returns_none` | invariant-checking | Externally checks absent-state behavior for silver hydration. Keep as narrow repository behavior coverage. |
| `test_repository.py` | `test_snapshot_upsert_keeps_latest` | mirror | **Flagged stale-price blind spot:** both calls use `_tick_value` defaults with `trade_time="090301"` and `business_date="20260601"`, so the test cannot construct a stale/fresh ordering scenario. It only proves last writer wins for equal text time. Replace with I2/I3/I4 property tests. |
| `test_handler.py` | `test_handler_persists_bronze_silver_and_snapshot_in_one_bucket` | mirror | Mirrors the happy-path pipeline for arrival-ordered ticks in one bucket. It checks transformation results but does not permute arrivals or assert event-time snapshot selection. Migrate snapshot coverage to I2. |
| `test_handler.py` | `test_handler_rolls_back_all_writes_when_snapshot_fails` | invariant-checking | Checks externally visible transaction atomicity across bronze/silver/snapshot writes. Keep as meaningful failure-path coverage; it is orthogonal to the five price-staleness invariants. |
| `test_handler.py` | `test_handler_hydrates_live_bucket_after_restart` | invariant-checking | Checks restart hydration for an in-order live bucket. Keep as restart behavior coverage and extend future replay tests under I1/I2. |
| `test_handler.py` | `test_handler_duplicate_kafka_message_does_not_double_count_silver` | mirror | Prevents double counting for the same `TickMessage` object/offset only. It does not cover same logical tick at a new offset because no logical `event_id` exists yet. Migrate to I1 after the event-id contract is implemented. |
| `test_handler.py` | `test_handler_restart_then_duplicate_replay_does_not_hydrate_and_double_count` | mirror | Same limitation as above: replay is represented by the same Kafka offset, so it mirrors current offset-key behavior instead of logical replay safety. Migrate to I1/I2 replay properties. |
| `test_handler.py` | `test_handler_bounds_aggregator_and_hydrated_keys_across_many_buckets` | mirror | Flags private internal-state assertions: `len(handler._aggregator._bars)`, `len(handler._hydrated_keys)`, and exact `handler._hydrated_keys == {...}`. Keep only if rewritten to assert public memory/DB behavior; it does not establish a data-contract invariant. |
